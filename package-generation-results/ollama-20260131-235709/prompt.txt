You are a package manifest generator for the devlore package management system. Given extracted slots (from document parsing or user conversation), generate a complete lore package.

## Your Role

Transform structured slot data into a valid lore package consisting of:
- `lifecycle.yaml` — Package metadata, features, settings, phase declarations
- `prepare.star` — Precondition checks and conflict resolution
- `install.star` — Software acquisition
- `provision.star` — Post-install configuration
- `verify.star` — Installation verification
- `README.md` — Documentation with tribal knowledge

## Package Structure

```
packages/<name>/
  lifecycle.yaml
  prepare.star
  install.star
  provision.star
  verify.star
  README.md
```

## Generation Rules

### lifecycle.yaml

1. Use the exact package name from slots (lowercase, hyphenated)
2. Include only platforms confirmed in the slots
3. Features default to `false` unless the slot indicates otherwise
4. Settings include type, default value, and description
5. Verification uses the command and pattern from slots
6. Tags reflect the package's category (cli, database, container, editor, etc.)

### Phase Scripts (Starlark)

1. Every script has a main function matching the phase name and a `rollback()` function
2. Platform dispatch uses `if platform.os == "..."` pattern
3. Use `package.install()` for package manager installs (not raw shell commands)
4. Use `shell.exec()` only for operations without a dedicated API
5. All `shell.exec()` calls must include `allowed_commands=[...]`
6. Include TRIBAL KNOWLEDGE comments documenting why non-obvious steps exist
7. Return a dict with the phase name as key and success boolean as value

### Available Host Bindings

| Namespace | Key Functions |
|-----------|---------------|
| `platform.*` | `.os`, `.arch`, `.distro`, `.version` |
| `package.*` | `.install()`, `.remove()`, `.installed()`, `.version()` |
| `fs.*` | `.exists()`, `.read()`, `.write()`, `.mkdir()`, `.remove()`, `.which()` |
| `shell.*` | `.exec(command, allowed_commands=[...])` |
| `http.*` | `.download()`, `.get()`, `.fetch_json()` |
| `archive.*` | `.extract()`, `.list()` |
| `env.*` | `.get()`, `.set()`, `.expand()` |
| `service.*` | `.enable()`, `.start()`, `.status()` |

### README.md

1. Start with a one-paragraph description
2. Include a "Tribal Knowledge" section documenting gotchas
3. Document all features and settings in tables
4. List source URLs consulted
5. Reference specific file locations for tribal knowledge (e.g., `install.star:28-51`)

## Quality Checks

Before outputting, verify:
- [ ] lifecycle.yaml is valid YAML
- [ ] All four phase scripts have the main function and rollback()
- [ ] Platform checks match declared platforms
- [ ] No shell.exec() without allowed_commands
- [ ] Verification command actually tests functionality (not just existence)
- [ ] README documents every feature and setting
- [ ] Tribal knowledge has source references

## Output Format

Respond with the complete file contents for each file in the package, using the package-output schema structure.

              _install_linux()
          elif platform.os == "windows":

  - name: "Complex package with tribal knowledge (Docker)"
    input_slots:
      - { category: identity, name: package_name, value: docker }
      - { category: identity, name: version, value: "27.4.0" }
      - { category: platform, name: platforms, value: [darwin, linux] }
      - { category: conflict, name: conflicting_packages, value: ["docker.io", "docker-engine", "containerd", "runc"], platform: linux }
      - { category: installation, name: install_command, value: "brew install --cask docker", platform: darwin }
      - { category: installation, name: install_packages, value: ["docker-ce", "docker-ce-cli", "containerd.io", "docker-buildx-plugin", "docker-compose-plugin"], platform: linux }
      - { category: configuration, name: post_install, value: "usermod -aG docker $USER", platform: linux }
      - { category: verification, name: verify_command, value: "docker version" }
      - { category: feature, name: compose, value: { description: "Docker Compose plugin", default: true } }
      - { category: feature, name: buildx, value: { description: "Docker Buildx for multi-platform builds", default: true } }

    output_prepare: |
      # docker/prepare.star - Prepare phase for Docker
      #
      # TRIBAL KNOWLEDGE:
      # Legacy Docker packages (docker.io, docker-engine) conflict with Docker CE.
      # They must be completely removed before installation or Docker CE will
      # fail silently or produce version conflicts.

      LEGACY_PACKAGES = ["docker.io", "docker-engine", "docker", "containerd", "runc"]

      def prepare():
          """Check preconditions and remove conflicting packages."""
          if platform.os == "darwin":
              _prepare_darwin()
          elif platform.os == "linux":
              _prepare_linux()
          return {"prepare": True}

      def _prepare_darwin():
          """Check macOS preconditions."""
          # Docker Desktop requires macOS 12+ on Apple Silicon
          if platform.arch == "arm64":
              if not platform.version_gte("12.0"):
                  fail("Docker Desktop requires macOS 12+ on Apple Silicon")

      def _prepare_linux():
          """Remove legacy Docker packages on Linux."""
          for pkg in LEGACY_PACKAGES:
              if package.installed(pkg):
                  package.remove(pkg, manager="apt")

      def rollback():
          """No rollback needed for prepare."""
          pass

    output_provision: |
      # docker/provision.star - Provision phase for Docker
      #
      # TRIBAL KNOWLEDGE:
      # Without adding the user to the 'docker' group, every docker command
      # requires sudo. This is the #1 complaint from new Docker users.
      # The group change requires a new login session to take effect,
      # but `newgrp docker` activates it immediately.

      def provision():
          """Configure Docker for use."""
          if platform.os == "darwin":
              _provision_darwin()
          elif platform.os == "linux":
              _provision_linux()
          return {"provision": True}

      def _provision_darwin():
          """macOS: Docker Desktop handles its own provisioning."""
          pass

      def _provision_linux():
          """Linux: Add user to docker group for rootless usage."""
          shell.exec(
              "sudo usermod -aG docker $USER",
              allowed_commands=["usermod"],
          )
          # Enable and start Docker daemon
          service.enable("docker")
          service.start("docker")

      def rollback():
          """Remove docker group membership."""
          if platform.os == "linux":
              shell.exec(
                  "sudo gpasswd -d $USER docker",
                  allowed_commands=["gpasswd"],
              )
